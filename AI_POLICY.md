# AI Policy
As an open source library, MIT App Inventor is supported by external contributions in the
form of Pull Requests (PRs).
The following document outlines our policy regarding the use of AI tools when
making contributions to the project.

Creating guidelines on the use of AI allows us to:
- Maintain a high-quality codebase
- Reduce the review burden on the App Inventor team and contributors
- Provide accessible opportunities for new contributors

## Human in the loop
PR summaries and GitHub comments should be written by a human unless you need
AI translation support. AI tools often produce verbose summaries even for
small changes, which makes them difficult to review. Writing the PR summary
yourself also ensures that you fully understand the code you’ve submitted.

Humans are reading and reviewing all the PRs that you submit, so we ask that
you make it easy for a human to understand what your code does and why.

## Good first issues
We label some GitHub issues as `help wanted` and `hints provided` for developers
who are new to the project. These issues are intentionally beginner-friendly,
well documented, and self-contained.

The purpose of solving a `help wanted` issue is to learn about MIT App Inventor
and the workflows that we use. Therefore, AI should not be used to write code or PR
summaries when solving these issues. If you have questions about an issue, you can
always leave a comment on GitHub and the team will be happy to assist you.

## AI disclosure
If AI tools were used to create content (such as code, documentation, or
configuration) that is submitted as part of a PR, please disclose this in the PR
summary. This should simply be a sentence or two describing how, and to what
extent, you used the tool.

## Enforcement
Pull requests should always be more beneficial to the project than the time they
take to review. The team may close PRs that violate this policy or are otherwise
too lengthy to review efficiently.
